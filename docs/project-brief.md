# 项目任务书：今日角色（MVP）

## 0. 给 AI 编码助手的总指令
- 你是本项目的开发助手。先读完整任务书，再按“开发顺序”逐步实现。
- 每个里程碑结束时，项目必须能运行、可手动走通主流程。
- 严格按 MVP 范围开发，不要自行增加社交裂变、双人对照、AI 聊天、真实支付、复杂心理测评。
- 所有生成文案通过 `generator` 接口输出；MVP 先用规则模板，预留 LLM 接口，不要强依赖外部 API。
- 所有结论必须包含“数据锚点”，例如“过去 7 天有 5 天出现‘累’”。禁止诊断性、人格定性词汇。
- 代码需有 README：如何运行、如何测试、如何切换本地/云端数据。

## 1. 产品一句话
一个每天花 5 秒记录状态、逐步生成“个人角色资料卡”的自我认知小程序。免费用户每天可记录并看到即时反馈；付费用户解锁更深的周/月解读和行动建议。

## 2. MVP 范围（必须做）
1. 每日记录：选状态 + 选场景 + 可选一句话，5 秒内完成。
2. 今日角色碎片：记录后立即返回一个词/一句话，必须挂靠当天选择。
3. 周快照：最近 7 天记录达到 3 天后可生成，展示 2 个模式，至少 1 个尽量“反常识但可验证”。
4. 月角色卡：当月记录达到 10 天后可生成基础版，包含状态分布、高频场景、一个例外/张力、一个轻量行动建议。
5. 免费/付费分层：免费层完整可用；付费层用 mock 权益开关控制“深度解读/历史对比/行动建议”，暂不接真实支付。
6. 设置与隐私：查看隐私说明、清空全部数据、导出数据（JSON 即可）。
7. 数据层可替换：MVP 可先 `wx.storage` 本地存储；后续可切云开发，不改页面逻辑。

## 3. 明确不做（非目标）
- 不做分享裂变、邀请奖励、双人对照。
- 不做 AI 聊天、真人咨询、心理诊断、人格测评。
- 不做真实微信支付；只做付费页占位和 mock 订阅状态。
- 不做复杂社交、排行榜、评论。
- 不把“每日记录”或“基础月卡”锁在付费墙后。

## 4. 建议技术栈
- 微信小程序原生 + TypeScript。
- 页面轻量，不引入重型 UI 框架。
- 数据访问抽象为 `repository`：
  - `LocalRepository`：wx.storage，MVP 默认。
  - 预留 `CloudRepository` 接口，不要求本期实现。
- 文案生成抽象为 `RoleGenerator`：
  - `RuleBasedGenerator`：MVP 实现。
  - `LLMGenerator`：预留接口，不要求本期接入。

## 5. 核心页面
1. `pages/index` 首页/每日记录
2. `pages/today-result` 今日角色碎片结果
3. `pages/weekly` 本周角色快照
4. `pages/monthly` 本月角色卡
5. `pages/paywall` 付费权益说明（mock 开通）
6. `pages/settings` 设置/隐私/清空数据/导出数据

底部导航建议：记录 / 角色 / 我的。

## 6. 数据模型
```ts
type Status = '平稳' | '紧绷' | '低电量' | '兴奋' | '烦躁' | '麻木';
type Scene = '工作' | '关系' | '独处' | '身体' | '家庭';

interface DailyEntry {
  id: string;
  userId: string;
  date: string;        // YYYY-MM-DD，本地时区
  status: Status;
  scene: Scene;
  note?: string;       // 可选，最多 100 字
  createdAt: number;
  updatedAt: number;
}

interface Entitlement {
  userId: string;
  isPro: boolean;
  plan: 'free' | 'mock_pro';
  expiresAt?: number;
}

interface WeeklySnapshot {
  id: string;
  userId: string;
  weekStart: string;   // YYYY-MM-DD 周一
  patterns: Pattern[];
  generatedAt: number;
}

interface Pattern {
  title: string;
  description: string; // 必须含数据锚点
  isCounterIntuitive: boolean;
}

interface MonthlyCard {
  id: string;
  userId: string;
  month: string;       // YYYY-MM
  statusDistribution: Record<Status, number>;
  topScenes: { scene: Scene; count: number }[];
  tension?: string;    // 例外/张力
  actionSuggestion?: string;
  generatedAt: number;
}
```

约束：同一用户同一天只能有一条 DailyEntry，重复提交为更新。

## 7. 生成规则（MVP 规则模板）
### 7.1 今日角色碎片
输入：当天 status、scene、note、最近 7 天记录。
输出：一个标签 + 一句解释。
示例：
- 标签：“硬撑的协调者”
- 解释：“今天你在‘工作’场景下记录为‘紧绷’，过去 7 天有 4 天出现类似组合。”
规则要求：
- 必须引用当天 status 和 scene。
- 若最近 7 天有重复组合，加入次数锚点。
- 禁止“你就是……的人”这类定性。

### 7.2 周快照
条件：最近 7 天有效记录 >= 3 天。
输出 2 个 Pattern：
1. 高频状态/场景组合。
2. 反常识模式，优先规则：
   - 找本周状态最低的一天，若不在周一/周五，则描述“你的低点不在通常以为的周初/周末”。
   - 若某场景的平均状态明显低于整体，描述场景与状态的共现。
   - 若没有明显反常识，则输出“本周最稳定的场景/最波动的场景”。
每个 Pattern 必须含数据锚点。

### 7.3 月角色卡
条件：当月有效记录 >= 10 天。
包含：
- 状态分布：各状态天数。
- 高频场景 Top 2。
- 例外/张力：某场景下状态与整体平均相反，或某状态只在特定场景出现。
- 轻量行动建议：基于高频脆弱时段/场景给一个小调整。
示例建议：“下周三晚间尽量不排会议；你的记录显示该时段低状态更集中。”
禁止医疗、诊断、治疗建议。

## 8. 付费分层
免费层：
- 无限量每日记录。
- 今日角色碎片。
- 周快照基础版（2 个 Pattern）。
- 月角色卡基础版（状态分布 + 高频场景 + 例外/张力一句）。

Mock 付费层：
- 月卡完整解读：Pattern 的触发原因、共现分析。
- 历史对比：本月 vs 上月。
- 基于角色卡的行动建议完整版。
- 数据导出。

实现要求：`Entitlement.isPro` 控制展示；付费页提供“模拟开通/关闭”按钮，仅用于开发测试。不要接微信支付。

## 9. 隐私与文案红线
- 设置页必须有：隐私说明、清空全部数据、导出 JSON。
- 清空数据必须是真删除本地数据。
- 文案禁止：诊断、抑郁/焦虑倾向、人格类型定性、治疗建议。
- 健康相关只写“状态参考”，不替代专业建议。
- 不做分享奖励、不做“分享解锁”。

## 10. 开发顺序（按里程碑）
M1 项目脚手架
- 小程序页面与导航；TypeScript；repository 接口；本地存储实现。
- 验收：能进入 6 个页面，无报错。

M2 每日记录 + 今日碎片
- 表单、校验、同日更新；RuleBasedGenerator 生成今日碎片；结果页展示。
- 验收：5 秒内完成记录；当天重复记录更新；碎片含数据锚点。

M3 周快照
- 最近 7 天聚合；>=3 天可生成；2 个 Pattern；反常识规则。
- 验收：无足够数据时显示引导；有数据时至少 1 个 Pattern 标为反常识或说明无。

M4 月角色卡
- 当月聚合；>=10 天可生成；状态分布、Top 场景、张力、行动建议。
- 验收：基础版免费可见；完整解读受 isPro 控制。

M5 权益与设置
- mock 付费页；isPro 开关；设置/隐私/清空/导出。
- 验收：免费/付费切换影响深度内容；清空后无残留；导出 JSON 可读。

M6 测试与 README
- 对生成规则写单元测试（若框架允许）；手动测试清单；README。
- 验收：主流程可跑通；README 含运行、测试、数据切换说明。
