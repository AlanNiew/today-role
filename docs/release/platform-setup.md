## 1. 建议执行顺序

1. **先定名称**（名称影响备案与头像/简介口径）。
2. 填基础信息：名称 + 头像 + 简介（三项要互相对得上）。
3. 补服务类目（审核通过后主营类目修改次数有限，一次选对）。
4. 填用户隐私保护指引（本项目不收集信息，选「不收集」）。
5. 提交小程序备案（**可与开发并行，但发布上架前必须通过**）。
6. 开发者工具上传 → 后台设为体验版 → 加体验成员 → 按 `docs/manual-test.md` 回归。
7. 提交审核（审核默认用开发版，我们的调试面板/Mock Pro 默认隐藏，审核员看到的是干净版本）。
8. 审核通过 → 发布。发布前再确认备案已通过。

## 2. 小程序名称候选

**当前已确定名称：「今天什么角色」**（12 个字符，符合 4–30；对应 AppID `wxa1ec97c3aece4bea`）。以下候选保留作备选/记录，备案与简介均按「今天什么角色」保持一致。

规则：**4–30 个字符，1 个汉字算 2 个字符**；仅中文、数字、英文，不能含特殊符号/繁体/无意义字符；全平台唯一；不得含「最 / 第一 / 国家级」等违规词，不得侵权或冒充。

| 顺序 | 名称         | 字符数 | 说明                                   |
| ---- | ------------ | ------ | -------------------------------------- |
| 1    | 今日角色     | 8      | 与产品「每天一个角色碎片」一致，最推荐 |
| 2    | 今天什么角色 | 12     | 更口语，适合传播                       |
| 3    | 今日角色碎片 | 12     | 直接点题「碎片」                       |
| 4    | 一天一个角色 | 12     | 强调每日记录节奏                       |
| 5    | 角色日记本   | 10     | 偏「日记」定位                         |
| 6    | 今日状态手账 | 12     | 偏手账人群                             |

填的时候从 1 开始试，被占用就顺延；如果都被占用，可以加地名/无意义词会扣分，建议换一个语义相近的新组合，而不是堆叠字符。

注意：

- 名称一旦通过修改次数有限，先和头像/简介一起想好。
- 「今日角色」若显示已被占用，不要加「官方」「正版」等词强行区分，容易被拒。
- 头像、名称、简介三者要指向同一个产品，审核会对照。

## 3. 小程序简介（4–120 字符）

**A 版（推荐，可直接粘贴）**：

```text
记录每天的状态与场景，生成一句今天的角色碎片；周快照、月卡与历史回看，看清最近的变化。数据只存本机，不收集个人信息。
```

（58 个汉字；按「1 汉字=2 字符」的最严口径是 116 字符，仍在 120 内。）

**B 版（更功能化）**：

```text
每天 5 秒记录状态与场景，生成今日角色碎片；支持周快照、月卡与历史回看。无需登录，数据只存本机。
```

**C 版（最短）**：

```text
记录每日状态与场景，生成今日角色碎片，回看最近的变化。
```

简介红线：不写「最 / 第一 / 100%」、不承诺效果、不出现诊断/治疗/心理测评、不引导分享；要和服务类目、实际功能一致。

## 5. 服务类目

**首选：一级「工具」→ 二级「效率」**。理由：本产品是本地记录/自我管理工具，提供记录、统计与回看，不涉及医疗健康服务，工具类目通常无需额外资质。

备选（若下拉没有「效率」）：

- 「工具 / 备忘录」：记录类工具，语义最接近；
- 「工具 / 健康管理」：只有在前两者都没有时才考虑，且简介/审核备注要强调「仅记录与回看，不做健康评估」；
- 不建议：「社交 / 笔记」（偏内容社区，审核更重）、任何「医疗」类目（需资质，且与产品定位冲突）、「文娱」。

类目填写/说明理由（如后台要求填）：

```text
本小程序为工具类自我管理记录工具：用户记录每日状态与场景，本地生成数量/共现描述并支持周、月与历史回看；不提供医疗健康服务，不做诊断或建议，无需相关资质。
```

## 6. 用户隐私保护指引

路径：设置 → 服务内容声明 → 用户隐私保护指引。

本项目无登录、无网络请求、不采集任何个人信息，选择**不收集用户信息**（后台若要求逐项声明，全部选「不收集」）。

可粘贴的说明：

```text
本小程序不收集、不上传任何用户信息。用户记录的状态、场景与备注仅保存在用户设备本地；不获取微信头像、昵称、手机号、位置、相册、通讯录、剪贴板等信息；不接入网络请求、统计或广告 SDK。用户可在设置页导出或清空全部数据。
```

注意：后续如果加了云同步、登录、订阅消息、分享图片等能力，必须同步更新隐私指引，否则会被判「收集隐私未声明」。

## 7. 小程序备案

路径：小程序后台「备案」入口（截图中的「小程序备案 未备案」）。

### 材料

- **个人主体**：主体负责人身份证（正反面）、手机号、邮箱、应急联系电话、通讯地址；小程序负责人可复用主体负责人，需人脸核身。
- **非个人主体**：营业执照、法定代表人身份证、小程序负责人身份证（非法人需授权书）、手机号、邮箱。

### 流程与时长

填写备案信息 → 平台初审（约 1–2 个工作日）→ 工信部短信核验（收到短信后 24 小时内完成）→ 通管局审核（约 1–20 个工作日）→ 备案成功。

备案通过前不能发布上架，但**可以先上传体验版**做内测；备案可与开发并行。

### 填写要点

- 备案名称必须与小程序名称一致（当前为「今天什么角色」），所以**先定名再备案**。
- 服务内容选「工具 → 备忘录（记录类）」这一档；若后台选项不同，选语义最接近的记录类工具。
- 通信地址、应急电话必须真实可用，通管局可能回访。
- 备案信息变更（名称/主体/负责人）要及时更新，否则违反运营规范。

## 13. 上线后
