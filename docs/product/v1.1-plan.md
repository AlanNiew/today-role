# v1.1 改造方案：状态 × 场景分类升级（已实施）

> 状态：**已实施（2026-11-27）**，实施记录见 §13。实施前的评审见 `docs/product/taxonomy-review.md`。
> 本文档相对 `docs/project-brief.md`（v1.0 基线，只读）提出需求变更；变更已落地，任务书作为 v1.0 基线保留。

## 1. 一句话目标

把「6 状态 × 5 场景」升级为「**8 状态 × 5 生活领域**」，用一次数据迁移 + 一次 40 格标签重写，解决 v1.0 的三个根问题：

1. 缺「难过/低落」→ 加「低落」；
2. 正性表达力不足 → 加「开心」；
3. 场景维度混用/关系与家庭重叠/工作不含学习 → 统一 5 个生活领域：**工作/学习 · 人际 · 家庭 · 独处 · 身体**。

## 2. 目标模型

### 2.1 状态（8 个，2×4 网格）

| 行                    | 状态（左→右）            | 语义                       |
| --------------------- | ------------------------ | -------------------------- |
| 上排（情绪强/有起伏） | 兴奋、开心、紧绷、烦躁   | 高唤醒：正性两格、负性两格 |
| 下排（低能量/平静）   | 平稳、低落、低电量、麻木 | 低唤醒：正性一格、负性三格 |

定义（用于「说明」弹窗）：

- 兴奋＝激动、坐不住、上头
- 开心＝心情好、想笑、满足
- 平稳＝心情没有大起伏
- 紧绷＝心里发紧、放不下
- 烦躁＝容易上火、被打断
- 低落＝心里发闷、提不起劲
- 低电量＝累，但还有感觉
- 麻木＝暂时没什么感觉

### 2.2 场景（5 个生活领域）

| 场景      | 定义                           |
| --------- | ------------------------------ |
| 工作/学习 | 上班、开会、写材料、上课、备考 |
| 人际      | 朋友、伴侣、同事等来往         |
| 家庭      | 和家人相处                     |
| 独处      | 一个人待着                     |
| 身体      | 睡眠、运动、饮食、身体感受     |

### 2.3 状态参考值（仅用于排序/找模式）

| 状态   | 兴奋 | 开心 | 平稳 | 紧绷 | 烦躁 | 低落 | 低电量 | 麻木 |
| ------ | ---- | ---- | ---- | ---- | ---- | ---- | ------ | ---- |
| 参考值 | 7    | 6    | 5    | 4    | 3    | 2    | 1      | 0    |

说明：这是「能量 + 负性程度」的综合排序，**不代表好坏**；页面不展示该数字，只用于周/月找「低点」。排序本身可再讨论（例如烦躁与低落谁更低），一旦定稿写进 `development-notes.md`。

## 4. 数据模型与迁移

### 4.1 迁移映射

| 旧值                   | 新值                     |
| ---------------------- | ------------------------ |
| 场景「工作」           | 「工作/学习」            |
| 场景「关系」           | 「人际」                 |
| 场景「独处/身体/家庭」 | 不变                     |
| 状态（6 个）           | 不变（新增值不需要迁移） |

### 4.2 存储处理

存储键（前缀 `today-role.v1.`）需处理：

| 键                     | 处理                                                    |
| ---------------------- | ------------------------------------------------------- |
| `entries`              | 逐条映射 scene；status 原样保留；写回                   |
| `weeklySnapshots`      | **清空**（旧文案里含「关系/工作」，重新生成）           |
| `monthlyCards`         | **清空**（`statusDistribution`/`topScenes` 键值已过期） |
| `entitlement` / `user` | 不变                                                    |
| 新增 `meta`            | 记录 `taxonomyVersion: 2`，保证迁移幂等                 |

### 4.3 迁移实现

- 新增 `miniprogram/core/migration.ts`（纯函数，可单测）：
  - `migrateEntries(raw: unknown): { entries: DailyEntry[]; changed: number }`
  - `mapScene(scene: string): Scene`（未知值原样返回并计数，便于日志）
- `miniprogram/data/repository.ts` 在创建仓储前调用一次 `migrateStorageOnce(storage)`：
  - 读 `meta.taxonomyVersion`；`>= 2` 直接返回；
  - 映射 entries、删除两个缓存键、写 `meta`；
  - 异常时**不阻断启动**：记录错误并保留原数据（下次再试）。
- 导出：`schemaVersion` 改为 `2`；README/导出说明同步。
- **回滚限制**：迁移是单向的；发布 v1.1 后回退 v1.0 代码会读不懂新 scene 值。因此 v1.1 必须先在体验版验证通过再发布。

## 6. 新标签总表（8 × 5 = 40）

设计原则（沿用 v1.0 评审）：

1. 角色化名词（人/者/派），不贴人格、不诊断；
2. 低状态用「承认消耗 + 保留主动」的措辞，不用「亏欠/忽略/只够应付」；
3. 同母题不过度重复（v1.0 的「赶路人 ×3」已拆开）；
4. 全部通过文案红线扫描（`scripts/check-structure.mjs` + `tests/helpers.ts`）。

| 状态 \ 场景 | 工作/学习          | 人际                 | 家庭             | 独处             | 身体               |
| ----------- | ------------------ | -------------------- | ---------------- | ---------------- | ------------------ |
| 兴奋        | 全速推进的发起者   | 主动靠近的连接者     | 带动气氛的召集人 | 灵感在线的探索者 | 想动起来的行动派   |
| 开心        | 越做越顺的人       | 愿意多聊两句的人     | 好脾气的相处者   | 乐在其中的自处者 | 走路带风的人       |
| 平稳        | 按节奏推进的人     | 稳稳在场的陪伴者     | 维持日常的定心丸 | 自得其乐的整理者 | 留意信号的观察者   |
| 紧绷        | 硬撑的协调者       | 小心拿捏的沟通者     | 顾全各方的调度员 | 停不下来的复盘者 | 绷着弦的赶路人     |
| 烦躁        | 反复切回来的推进者 | 耐心在排队的回应者   | 先稳住场面的家人 | 想先关掉弹窗的人 | 一路小跑的救火队员 |
| 低落        | 撑着做完的坚持者   | 话变少了的人         | 安静在场的家人   | 慢慢消化的独处者 | 想先歇一歇的人     |
| 低电量      | 省电模式的工作者   | 先给自己留电的回应者 | 低音量参与的家人 | 安静充电的休整者 | 提前收工的照顾者   |
| 麻木        | 按部就班的打卡者   | 暂时离线的倾听者     | 照常运转的家人   | 放空中的待机者   | 把身体调成静音的人 |

### 与 v1.0 的差异

- **新增 10 格**：开心 × 5、低落 × 5。
- **改写 7 格**（低状态体面感）：
  - 低电量×人际关系：只够应付的回应者 → **先给自己留电的回应者**
  - 麻木×身体：忽略信号的赶路者 → **把身体调成静音的人**
  - 烦躁×独处：需要清静的反刍者 → **想先关掉弹窗的人**（去掉临床词「反刍」）
  - 烦躁×工作：被打断的推进者 → **反复切回来的推进者**
  - 烦躁×家庭：忍着不发的协调者 → **先稳住场面的家人**
  - 麻木×家庭：按流程走的家人 → **照常运转的家人**
  - 麻木×工作：例行公事的打卡者 → **按部就班的打卡者**
- **保留 23 格**（含「硬撑的协调者」「省电模式的工作者」「暂时离线的倾听者」等高识别格）。
- 场景改名后，原「工作」「关系」两列的格子随 key 平移，文案不变。

## 8. 测试计划

- **纯函数**：迁移映射（旧→新、未知值、幂等、缓存删除）、`isKnown*`、分数顺序。
- **生成器**：40 格标签完整性（类型层面已保证，补一条运行时遍历断言）；选 8 个代表组合断言标签与解释锚点。
- **红线**：40 格标签全部过 `BANNED_COPY`。
- **门控**：周 3 天 / 月 10 天在 8 状态下的边界不变。
- **导出**：`schemaVersion === 2`，新枚举值可被解析。
- **手动**（`docs/manual-test.md` 增补）：8 格网格在 320px/393px 下的换行与点击；场景 pills 不溢出；说明弹窗文案；月卡 8 行分布；迁移后旧记录场景已更名且缓存重建。

## 9. 发布与回滚

1. 开发前打 tag `v1.0.0`（当前 `71d740d`）作为回滚点。
2. 分支 `feat/taxonomy-v1.1`，完成后 `npm run check` + 手动清单，合并到 master。
3. `config.ts` 的 `appVersion` 改 `1.1.0`；后台版本号一致。
4. 导出 `schemaVersion: 2`；设置页提示「旧导出文件仍可回顾，但字段为 v1」。
5. 迁移为单向：发布 v1.1 后不可直接回退 v1.0 代码（新 scene 值会读不出）；回滚需保留旧数据备份或写反向迁移。
6. 体验版验证通过后再提审发布。
